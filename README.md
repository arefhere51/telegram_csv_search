# ربات جست‌وجوی CSV در Telegram

این پروژه فایل‌های CSV بزرگ را به‌صورت مرحله‌ای وارد یک دیتابیس SQLite می‌کند و امکان جست‌وجوی سریع و محدودشده را از طریق ربات Telegram فراهم می‌سازد.

ربات از header واقعی هر فایل استفاده می‌کند. بنابراین فایل‌های مختلف می‌توانند ستون‌های متفاوتی داشته باشند؛ برای مثال:

```csv
id,name,phone,address,email
7,ثمین,09120000000,تهران میدان انقلاب,samin@example.com
```

در این حالت، نتیجه با نام واقعی ستون‌ها نمایش داده می‌شود:

```text
id: 7
name: ثمین
phone: 09120000000
address: تهران میدان انقلاب
email: samin@example.com
```

تمام headerهای ردیف در نتیجه می‌آیند؛ اگر مقدار ستونی خالی باشد با `—` نشان داده می‌شود. در زمان دریافت فایل از Telegram، header به‌صورت دکمه‌های شیشه‌ای نمایش داده می‌شود و فقط ستون‌هایی که انتخاب می‌کنید وارد جست‌وجو می‌شوند. بااین‌حال، پس از یافتن رکورد، تمام ستون‌های همان ردیف از CSV اصلی نمایش داده می‌شوند.

> این نرم‌افزار فقط باید برای داده‌هایی استفاده شود که اجازه قانونی و مدیریتی ذخیره‌سازی و جست‌وجوی آن‌ها را دارید.

## امکانات اصلی

- جست‌وجوی دقیق روی شناسه، نام، تاریخ، تلفن و فیلدهای انتخاب‌شده

- جست‌وجوی متنی هم نتیجهٔ دقیق و هم واژه‌های طولانی‌ترِ شروع‌شده با همان واژه را می‌آورد؛ مثلاً «علی» می‌تواند «علی»، «علی امیری» و «علی حسینی» را هم‌زمان پیدا کند.
- انتخاب ستون‌های قابل جست‌وجو برای هر فایل با دکمه‌های شیشه‌ای
- نمایش تمام ستون‌های ردیف منطبق، حتی اگر در جست‌وجو انتخاب نشده باشند
- پشتیبانی از header متفاوت برای هر فایل
- نمایش نام واقعی ستون‌ها در نتایج
- حذف خودکار ستون‌های خالی از خروجی
- پشتیبانی از نام‌ها و متن فارسی
- نرمال‌سازی حروف عربی و فارسی و اعداد
- دریافت CSV از چت خصوصی Telegram
- پردازش streaming برای فایل‌های بزرگ
- نوار پیشرفت مرحله‌ای برای دانلود، ورود CSV، ساخت شاخص‌ها، جست‌وجو و ارسال فایل نتیجه
- شناسهٔ پیگیری مشترک در پیام ربات و لاگ‌های CMD برای پیدا کردن مرحلهٔ خطا
- جلوگیری از شکستن رکوردهای CSV هنگام تقسیم فایل
- نگهداری وضعیت import فایل‌ها
- حذف و import مجدد امن فایل‌های تغییرکرده
- پشتیبانی از Ubuntu/Debian، VPS، Railway، Docker و محیط‌های container
- ایجاد خودکار دیتابیس خالی در اولین اجرا، حتی بدون وجود CSV

## نصب سریع با یک دستور

پس از اینکه این پروژه را در GitHub خودتان قرار دادید و فایل `install.sh` در شاخه `main` قرار گرفت، روی سرور یا محیط موردنظر اجرا کنید:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh)
```

برای Railway، Docker و محیط‌های بدون systemd، حالت foreground را صریحاً مشخص کنید:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh) --mode foreground
```

اسکریپت نصب تک‌دستوری این کارها را انجام می‌دهد:

1. دریافت یا به‌روزرسانی پروژه از GitHub
2. تشخیص محیط اجرا
3. انتخاب systemd برای VPS واقعی یا foreground برای Railway/Docker
4. نصب وابستگی‌های Python
5. اجرای wizard تنظیمات
6. دریافت امن توکن ربات و آیدی عددی Telegram
7. ساخت فایل `.env`
8. ساخت دیتابیس خالی در صورت نبودن CSV
9. import فایل‌های موجود در صورت وجود
10. آماده‌کردن اجرای دائمی ربات

توکن در زمان ورود مخفی است و در خروجی چاپ نمی‌شود.

### گزینه‌های نصب

نمایش راهنما:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh) --help
```

نصب بدون import اولیه:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh) --skip-import
```

ساخت تنظیمات بدون اجرای ربات:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh) --no-start
```

اجبار به اجرای systemd:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh) --mode systemd
```

اجبار به اجرای container/foreground:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh) --mode foreground
```

> در حالت `auto`، ویزارد فقط زمانی systemd را انتخاب می‌کند که `systemctl` وجود داشته باشد و پردازش شماره ۱ سیستم واقعاً `systemd` باشد. به همین دلیل در Railway یا Docker با خطای systemd متوقف نمی‌شود.

## سؤال‌های wizard

در زمان اجرای wizard، سؤال‌های زیر پرسیده می‌شوند:

```text
Paste your BotFather token:
Enter numeric Telegram user ID(s), comma-separated:
Do your CSV files normally contain a header row? [y]:
CSV delimiter (one character) [,]:
CSV encoding [utf-8-sig]:
Allow authorized private-chat CSV uploads? [y]:
```

رمزگذاری پیش‌فرض `utf-8-sig` است. اگر فایل چند بایت ناسازگار داشته باشد، importer برای متوقف‌نشدن فایل را ادامه می‌دهد و آن بایت‌ها را با نویسهٔ جایگزین `�` نشان می‌دهد؛ تعداد markerها در لاگ انگلیسی ثبت می‌شود. اگر کل فایل با encoding دیگری ذخیره شده، مقدار `CSV_ENCODING` را در `.env` به encoding درست تغییر دهید تا متن اصلی دقیق‌تر حفظ شود.

گزینه حذف فایل منبع دیگر در wizard وجود ندارد؛ CSV باید برای hydrate کردن نتیجه‌ها همیشه نگه داشته شود.

### توکن ربات

توکن را از `@BotFather` دریافت کنید. نمونه شکل توکن:

```text
123456789:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

توکن را در GitHub یا پیام عمومی قرار ندهید.

### آیدی عددی Telegram

آیدی باید عددی باشد، نه username. نمونه صحیح:

```text
149772217
```

برای چند کاربر:

```text
149772217,123456789
```

نمونه‌های نادرست:

```text
@my_username
ID: 149772217
```

### پاسخ پیشنهادی برای CSVهای معمولی

```text
Header row: y
Delimiter: ,
Encoding: utf-8-sig
Allow uploads: y
Delete after import: n
```

## نصب روی VPS واقعی Ubuntu یا Debian

روی VPS واقعی که systemd فعال دارد، اجرا کنید:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/arefhere51/telegram_csv_search/main/install.sh)
```

ویزارد به‌صورت خودکار:

- کاربر سیستمی `csvsearch` را می‌سازد.
- virtualenv ایجاد می‌کند.
- وابستگی‌ها را نصب می‌کند.
- فایل systemd را نصب می‌کند.
- سرویس را فعال می‌کند.
- ربات را اجرا می‌کند.

بررسی وضعیت سرویس:

```bash
systemctl status telegram-csv-search
```

مشاهده لاگ زنده:

```bash
journalctl -u telegram-csv-search -f
```

لاگ‌های foreground در همان صفحهٔ CMD دیده می‌شوند. هر خط شامل زمان، سطح، شناسهٔ process/thread، نام فایل و شماره‌خط کد است. ربات برای هر پیام ورودی و مرحله‌های طولانی مثل دانلود، خواندن CSV، ساخت شاخص، جست‌وجو، ساخت/ارسال TXT و حذف دیتاست، رویدادهای انگلیسی ثبت می‌کند. برای بررسی یک عملیات، کد پیگیری‌ای را که ربات در پیام پیشرفت نشان می‌دهد پیدا کنید و در لاگ جست‌وجو کنید:

```bash
grep 'operation_id=AB12CD34' logs/bot.log
```

در محیط systemd:

```bash
journalctl -u telegram-csv-search --since '30 minutes ago' | grep 'operation_id=AB12CD34'
```

در CMD درصد دانلود و خواندن/نوشتن رکوردها از حجم یا شمارش واقعی محاسبه می‌شود. درصد بعضی مرحله‌های SQLite و جست‌وجو، پیشرفت مرحله‌ای/تقریبی است؛ متن مرحلهٔ فعال (برای مثال نام شاخصی که در حال ساخته‌شدن است) مشخص می‌کند ربات کجا مشغول است. در خطاهای برنامه traceback کامل ثبت می‌شود؛ توکن ربات و کلید دسترسی لینک Drive پیش از ثبت پالایش می‌شوند. متن جست‌وجو و محتوای ردیف‌های CSV در لاگ نوشته نمی‌شوند.

راه‌اندازی مجدد:

```bash
systemctl restart telegram-csv-search
```

## نصب و اجرا روی Railway

Railway معمولاً برنامه را داخل container اجرا می‌کند و systemd ندارد. بنابراین نباید از `systemctl` استفاده شود.

### تنظیمات Railway

در بخش **Variables** این متغیرها را اضافه کنید:

```env
TELEGRAM_BOT_TOKEN=توکن_واقعی_ربات
ALLOWED_USER_IDS=149772217
ADMIN_USER_IDS=149772217
ACCESS_MODE=private

DATA_DIRECTORY=/data/csv
DATABASE_PATH=/data/database/search.db
LOG_DIRECTORY=/data/logs

CSV_DELIMITER=,
CSV_ENCODING=utf-8-sig
CSV_HAS_HEADER=true
CSV_COLUMN_NAMES=column_1,column_2,name,birth_date,phone

UPLOAD_ENABLED=true
DELETE_CSV_AFTER_IMPORT=false
```

> بهتر است توکن را در بخش Variables تنظیم کنید، نه داخل فایل `.env` در GitHub.

### Start Command

در تنظیمات Railway، مقدار Start Command را این قرار دهید:

```bash
./railway_start.sh
```

این فایل:

1. Python داخل `venv` را در صورت وجود انتخاب می‌کند.
2. اگر CSV موجود باشد، آن را import می‌کند.
3. اگر CSV وجود نداشته باشد، import را رد می‌کند.
4. دیتابیس خالی را توسط `bot.py` ایجاد می‌کند.
5. ربات را در foreground اجرا می‌کند.

بنابراین می‌توانید بدون قرار دادن هیچ CSV اولیه‌ای ربات را بالا بیاورید و اولین فایل را از Telegram ارسال کنید.

### Volume در Railway

فایل‌های داخل container ممکن است بعد از redeploy یا restart پاک شوند. برای حفظ دیتابیس، CSVها و لاگ‌ها یک Railway Volume بسازید و آن را روی مسیر زیر mount کنید:

```text
/data
```

سپس این متغیرها را تنظیم کنید:

```env
DATA_DIRECTORY=/data/csv
DATABASE_PATH=/data/database/search.db
LOG_DIRECTORY=/data/logs
```

بدون Volume، دیتابیس و فایل‌های آپلودی ممکن است بعد از redeploy از بین بروند.

## اجرای دستی روی سرور

اگر virtualenv قبلاً ساخته شده است:

```bash
cd /telegram_csv_search
./venv/bin/python import_csv.py
./venv/bin/python bot.py
```

اگر پیام پیشرفت ورود ردیف‌ها به ۱۰۰٪ رسید ولی ساخت شاخص جست‌وجو به‌علت قفل SQLite تمام نشد، **فایل را دوباره آپلود نکنید**؛ ردیف‌ها قبلاً وارد شده‌اند. ابتدا ربات را متوقف کنید، سپس شاخص‌ها را از روی CSVهای موجود بازسازی کنید و ربات را دوباره اجرا کنید:

```bash
cd /telegram_csv_search
./venv/bin/python import_csv.py --rebuild-indexes
./venv/bin/python bot.py
```

Importer فایل‌های کامل و بدون تغییر را رد می‌کند و فقط شاخص‌ها را بازسازی می‌کند. ساخت شاخص‌ها برای دیتابیس چندمیلیونی ممکن است چند دقیقه طول بکشد؛ هنگام کار پیام انتظار و retry قفل SQLite در لاگ دیده می‌شود.

### کنترل رشد حجم دیتابیس

**CSV منبع اصلی داده است.** SQLite متن خام ردیف‌ها را تکرار نمی‌کند و فقط metadata فایل، offset بایتی شروع/پایان رکورد، کلیدهای نرمال‌شده ستون‌های انتخابی و FTS همان ستون‌ها را نگه می‌دارد. بعد از پیدا شدن نتیجه، متن اصلی مستقیماً از همان بازه بایتی CSV خوانده و parse می‌شود. این طراحی از CSVهای quoted چندخطی و `utf-8-sig` پشتیبانی می‌کند.

در نتیجه فایل‌های CSV داخل `DATA_DIRECTORY` باید همراه دیتابیس نگه داشته و backup شوند. حذف، جابه‌جایی یا تغییر فایل بعد از import باعث می‌شود نتیجه مربوط به آن فایل قابل hydrate نباشد. `DELETE_CSV_AFTER_IMPORT` فقط برای سازگاری تنظیمات قدیمی باقی مانده، نادیده گرفته می‌شود و فایل منبع حذف نخواهد شد.

فایل‌های آپلودی Telegram نام موقت یکتا دارند و ایمپورت دوباره همان CSV می‌تواند رکوردهای تکراری بسازد. حالت `DUPLICATE_MODE=exact` رکوردهای کاملاً یکسان را در هر فایل و با انتخاب ستون یکسان فقط یک‌بار index می‌کند؛ فایل‌های مختلف مستقل می‌مانند تا انتخاب جست‌وجوی هر فایل با فایل دیگر تداخل نکند. اگر تکرار رکوردها از نظر کسب‌وکار مهم است، آن را روی `keep` قرار دهید.

### ارتقا از دیتابیس قدیمی

schema جدید ستون‌های انتخاب‌شده را هم ذخیره می‌کند. دیتابیس نسخه ۲ که offset بایتی دارد هنگام اجرای نسخه جدید به‌صورت خودکار ارتقا می‌یابد و برای فایل‌های قبلی همه ستون‌ها را انتخاب‌شده فرض می‌کند؛ برای فایل‌های جدیدی که از تلگرام می‌فرستید، انتخاب ستون‌ها اعمال می‌شود. دیتابیس‌های قدیمی‌تر که `raw_fields_json` دارند ولی offset ندارند، عمداً با پیام واضح رد می‌شوند، چون ساخت offset دقیق برای CSV چندخطی از روی داده قدیمی امن نیست. برای داده‌های نسخه ۲، انتخاب قبلی عمداً حفظ می‌شود؛ بنابراین رکوردهای قدیمی همچنان با همه ستون‌هایشان جست‌وجو می‌شوند. اگر می‌خواهید فایل‌های قبلی هم فقط با ستون‌های انتخابی جدید قابل جست‌وجو باشند، از تمام CSVها و دیتابیس backup بگیرید، ربات را متوقف کنید، CSVهای قبلی را موقتاً به مسیری خارج از `DATA_DIRECTORY` منتقل کنید، دیتابیس و فایل‌های `-wal` و `-shm` را آرشیو/کنار بگذارید، ربات را با دیتابیس خالی بالا بیاورید و هر CSV را دوباره از چت خصوصی بفرستید و ستون‌هایش را انتخاب کنید. CSVهایی که داخل `DATA_DIRECTORY` باقی بمانند توسط importer معمولی با همه ستون‌ها وارد می‌شوند.

در دیتابیس‌های قدیمی‌تر از نسخه ۲ که `raw_fields_json` دارند ولی offset ندارند، فایل منبع را نگه دارید، از دیتابیس backup بگیرید و پس از توقف ربات دیتابیس قدیمی را کنار بگذارید؛ سپس از نو بسازید:

```bash
./venv/bin/python import_csv.py
```

اگر قبلاً رکوردها حذف شده‌اند یا فایل‌ها چند بار ایمپورت شده‌اند، فضای آزاد فایل SQLite خودکار به سیستم‌عامل برنمی‌گردد. پس از اطمینان از توقف ربات و داشتن فضای موقت کافی، یک‌بار فشرده‌سازی را اجرا کنید:

```bash
./venv/bin/python import_csv.py --vacuum
```

گزینه `--vacuum` دیتابیس را بازنویسی می‌کند و ممکن است برای دیتابیس‌های چندگیگابایتی زمان‌بر باشد؛ آن را در زمان کم‌بار اجرا کنید. فایل‌های `search.db-wal` و `search.db-shm` نیز بخشی از مصرف موقت فضای دیسک هستند و بعد از checkpoint/بسته‌شدن اتصال معمولاً کوچک یا حذف می‌شوند.

در محیط Railway/Docker، دستور بهتر این است:

```bash
cd /telegram_csv_search
./railway_start.sh
```

## اجرای بدون CSV و دریافت اولین فایل از Telegram

اگر پوشه `data` خالی باشد، این رفتار طبیعی است:

```text
No CSV/TXT source files found; starting with an empty database.
```

پس از آن ربات اجرا می‌شود و می‌توانید:

1. در چت خصوصی Telegram دستور `/start` را بفرستید.
2. فایل CSV دارای header را ارسال کنید.
3. ربات فایل را دانلود می‌کند و ردیف اول را به‌عنوان header می‌خواند.
4. نام ستون‌ها در دکمه‌های شیشه‌ای نمایش داده می‌شود؛ ستون‌های قابل جست‌وجو را انتخاب کنید.
5. فایل پس از تأیید انتخاب‌ها در صف import قرار می‌گیرد.
6. فقط مقادیر ستون‌های انتخاب‌شده وارد index جست‌وجو می‌شوند.
7. نتیجه‌ی پیدا‌شده از CSV اصلی hydrate می‌شود و تمام ستون‌های همان ردیف را نشان می‌دهد.

## فرستادن CSV از Telegram

### فایل‌های بزرگ و سقف واقعی تلگرام

سقف داخلی ربات به‌طور پیش‌فرض **۱۰ گیبی‌بایت** است (`UPLOAD_MAX_BYTES=10737418240`) و می‌توان آن را در `.env` تغییر داد. اما این فقط سقف برنامه است و محدودیت‌های خود تلگرام را حذف نمی‌کند.

برای دریافت فایل‌های بزرگ‌تر از ۲۰ مگابایت، باید **Local Bot API Server رسمی** واقعاً در حال اجرا باشد و ربات به آن وصل شود. مستند رسمی می‌گوید سرور محلی فایل‌ها را بدون سقف حجمی دانلود می‌کند؛ سقف ۲۰۰۰ مگابایت در همان مستند برای **ارسال فایل از طرف Bot API** است، نه دانلود فایل دریافتی با `getFile` [1] [2].

فایل تکی‌ای که کاربر از برنامه Telegram می‌فرستد، طبق راهنمای رسمی حداکثر ۲ گیگابایت برای حساب عادی و ۴ گیگابایت با Premium است [3]. بنابراین برای فایل‌های بالاتر از ۳ گیگابایت، فرستنده باید Premium داشته باشد؛ فایل تکی بزرگ‌تر از ۴ گیگابایت را نمی‌توان از مسیر معمول ارسال فایل تلگرام فرستاد. برای فایل‌های بزرگ‌تر از آن، از `split_csv_for_bot.py` با `--has-header` استفاده کنید یا فایل را مستقیم روی سرور قرار دهید و importer را اجرا کنید.

اگر نمی‌خواهید فایل چندگیگابایتی را از Telegram بفرستید یا محدودیت ارسال Telegram را دارید، راه ساده‌تر **لینک Google Drive** است؛ مراحل آن در بخش «دریافت فایل چندگیگابایتی از Google Drive» آمده است.

انتخاب «بله» در installer **سرور Local Bot API را نصب یا اجرا نمی‌کند**؛ فقط نشانی API را در تنظیمات ربات می‌نویسد. سرور رسمی باید جداگانه با حالت `--local` اجرا شده باشد و برای همان bot token به کار برود. در `.env`، نشانی‌ها باید به همان سرور و از دید فرایند ربات قابل دسترسی باشند:

```env
TELEGRAM_BASE_URL=http://127.0.0.1:8081/bot
TELEGRAM_FILE_BASE_URL=http://127.0.0.1:8081/file/bot
UPLOAD_MAX_BYTES=10737418240
```

اگر ربات و Local Bot API در کانتینرهای جدا هستند، به‌جای `127.0.0.1` نام میزبان/سرویس قابل دسترسی در شبکه‌ی آن‌ها را وارد کنید. در حالت local ممکن است `getFile` مسیر مطلق فایل را برگرداند؛ کد آن را مستقیماً کپی می‌کند، پس مسیر داده‌ی سرور Bot API باید داخل کانتینر ربات نیز mount شده باشد. اگر پس از انتخاب Local Bot API هنوز خطای `File is too big` می‌بینید، تنظیمات `.env` و اجرای سرور محلی را بررسی کنید؛ احتمالاً ربات هنوز به API ابری وصل است یا سرور محلی با پیکربندی درست فعال نیست.

دریافت در ربات به‌صورت جریانی روی دیسک انجام می‌شود و فایل کامل در RAM بارگذاری نمی‌شود. فضای کافی برای فایل موقت، دیتابیس SQLite، WAL و شاخص‌ها لازم است.

### پیشرفت زنده‌ی دریافت و ورود اطلاعات

پس از ارسال فایل، ربات یک پیام وضعیت را مرتب ویرایش می‌کند و نوار گرافیکی، درصد، حجم دریافت‌شده، سرعت و مرحله فعلی را نشان می‌دهد. پس از دانلود، پیش از شروع import، دکمه‌های انتخاب ستون قابل جست‌وجو نمایش داده می‌شوند:

```text
⬇️ دانلود فایل
bank.csv
[██████████░░░░░░░░░░]  50.0%
حجم: 950.0 MiB / 1.9 GiB
سرعت: 18.4 MiB در ثانیه
```

در مرحله ورود اطلاعات نیز همان پیام با تعداد ردیف‌های خوانده‌شده و درج‌شده، سرعت و درصد تقریبی فایل به‌روزرسانی می‌شود. در جست‌وجو، اگر ۵ نتیجه یا کمتر پیدا شود همه در پیام نشان داده می‌شوند؛ اگر بیشتر از ۵ نتیجه باشد، پیش‌نمایش نتایج ارسال نمی‌شود و فقط یک یا چند فایل متنی UTF-8 شامل همه‌ی نتیجه‌ها فرستاده می‌شود. نام فایل شامل عبارت جست‌وجو است و تعداد کل رکوردهای پیدا‌شده زیر فایل (در کپشن تلگرام) می‌آید. هر رکورد با خط «━━━━━━━━━━━━━━━━━━» از رکورد بعدی جدا می‌شود. هنگام بارگذاری، پیام «در حال ارسال» نشان داده می‌شود و ربات تا ۳۰ ثانیه برای ارسال هر فایل منتظر می‌ماند؛ اگر مهلت تمام شود، پیام خطای ارتباط می‌دهد. فایل‌ها برای سازگاری با محدودیت ارسال تلگرام به قطعه‌های حداکثر حدود ۴۰ مگابایتی تقسیم می‌شوند. فاصله پیش‌فرض ویرایش پیام ۳ ثانیه است و با این متغیر قابل تغییر است:

```env
UPLOAD_PROGRESS_INTERVAL_SECONDS=3
```

برای آپلود موفق، شرایط زیر باید برقرار باشد:

- فایل CSV دارای سرستون در چت خصوصی ربات ارسال شود.
- آیدی فرستنده مدیر ربات یا کاربر ثبت‌شده باشد (در حالت عمومی هم بارگذاری آزاد نیست).
- دست‌کم یک ستون از دکمه‌های شیشه‌ای انتخاب شود.
- `UPLOAD_ENABLED=true` باشد.
- پسوند فایل `.csv` یا `.txt` باشد.
- حجم فایل از `UPLOAD_MAX_BYTES` بیشتر نباشد.
- فضای ذخیره‌سازی کافی وجود داشته باشد.

روند پیام‌ها معمولاً چنین است:

```text
فایل دریافت شد
دریافت فایل آغاز شد
دریافت کامل شد
در صف ورود اطلاعات قرار گرفت
ورود اطلاعات آغاز شد
پیشرفت ورود اطلاعات
ورود اطلاعات کامل شد
```

فایل اصلی بعد از ورود اطلاعات همیشه نگه داشته می‌شود، زیرا منبع اصلی داده است و نتیجه جست‌وجو با offset مستقیماً از آن خوانده می‌شود. مقدار قدیمی `DELETE_CSV_AFTER_IMPORT=true` نادیده گرفته خواهد شد.

## دریافت فایل چندگیگابایتی از Google Drive

اگر فایل ۲ تا ۳ گیگابایت است، لازم نیست آن را به Telegram بفرستید: فایل CSV را در Drive بگذارید و **لینک همان فایل** را در گفت‌وگوی خصوصی ربات بفرستید. ربات فایل را تکه‌تکه روی دیسک دریافت می‌کند، ردیف اول را می‌خواند، headerها را در دکمه‌ها نشان می‌دهد و بعد از انتخاب شما همان مسیر معمول ورود اطلاعات را اجرا می‌کند. فقط ستون‌های انتخاب‌شده برای جست‌وجو index می‌شوند؛ همه‌ی ستون‌های ردیف نتیجه همچنان حفظ می‌شوند.

### دریافت لینک Drive بدون Google Cloud API

برای این روش **نیازی به Google Cloud، فعال‌کردن Drive API، ساخت Service Account یا گذاشتن کلید روی سرور نیست**. در عوض، فایل باید برای هرکسی که لینک را دارد قابل دریافت باشد:

1. روی فایل CSV در Google Drive گزینهٔ **Share / اشتراک‌گذاری** را بزنید.
2. در بخش **General access / دسترسی عمومی**، گزینهٔ **Anyone with the link / هرکسی که لینک را دارد** را انتخاب کنید و سطح دسترسی را **Viewer / مشاهده‌گر** بگذارید.
3. لینک همان فایل را در گفت‌وگوی خصوصی ربات بفرستید. ربات آن را به‌صورت جریانی روی دیسک می‌گیرد و سپس headerها و دکمه‌های انتخاب ستون را نشان می‌دهد.

> این سادگی یک ملاحظهٔ حریم خصوصی دارد: هر فردی که لینک فایل را داشته باشد می‌تواند خود فایل را باز کند. اگر نمی‌خواهید فایل با لینک قابل‌دسترسی باشد، از این روش استفاده نکنید؛ این نسخهٔ بدون API نمی‌تواند فایل خصوصی Drive را بخواند.

لینک‌های فایل مانند `drive.google.com/file/d/...` و `drive.google.com/open?id=...` پذیرفته می‌شوند؛ `resourcekey` موجود در لینک هم منتقل می‌شود و صفحهٔ تأیید دانلود فایل‌های بزرگ دنبال می‌شود. لینک پوشه و فایل‌های بومی Google Sheets/Docs قابل ورود مستقیم نیستند؛ اگر داده در Sheet است، ابتدا آن را به CSV دانلود کنید. دستور `/drive_setup` همین مراحل اشتراک‌گذاری را داخل ربات یادآوری می‌کند.

حد برنامه از همان `UPLOAD_MAX_BYTES` پیروی می‌کند و پیش‌فرض آن ۱۰ گیبی‌بایت است. دریافت به‌صورت جریانی انجام می‌شود و کل فایل در حافظه نگه داشته نمی‌شود؛ بااین‌حال برای خود فایل، پایگاه داده و شاخص‌ها فضای دیسک کافی لازم است. اگر خطای دسترسی گرفتید، دسترسی لینک را روی «هرکسی که لینک را دارد — مشاهده‌گر» بگذارید.

## دسترسی، مدیریت کاربران و نام هدر خروجی

مدیر اصلی با `ADMIN_USER_IDS` مشخص می‌شود. اگر این متغیر در `.env` خالی باشد، اولین شناسه از `ALLOWED_USER_IDS` مدیر می‌شود؛ توصیه می‌شود شناسه‌ی مدیر را صریحاً تنظیم کنید. فهرست کاربران و حالت دسترسی بعد از bootstrap در SQLite ذخیره می‌شوند و با restart باقی می‌مانند.

دستورهای مدیر در گفت‌وگوی خصوصی ربات:

```text
/admin
/user_add 123456789
/user_remove 123456789
/access private
/access public
/header_set NATIONAL_CODE = کد ملی
/header_aliases
/header_remove NATIONAL_CODE
/database
```

`/admin` پنل مدیریت را باز می‌کند؛ از دکمه‌های آن می‌توان حالت عمومی/خصوصی را عوض کرد یا کاربران ثبت‌شده را حذف کرد. `/database` فهرست فایل‌های ایندکس‌شده را با دکمه‌های شیشه‌ای نشان می‌دهد؛ انتخاب فایل، جزئیات آن و دکمهٔ تأیید حذف را نمایش می‌دهد. پس از تأیید، رکوردها و ورودی‌های FTS آن فایل از SQLite حذف می‌شوند و دیگر در نتایج جست‌وجو نمی‌آیند. CSV خام حذف نمی‌شود؛ به پوشه‌ای هم‌سطح `DATA_DIRECTORY` با پسوند `_deleted_sources` منتقل می‌شود تا ابزار import دوباره آن را پیدا نکند. این کار فضا را آزاد نمی‌کند؛ فایل آرشیوی را فقط در صورت نیاز جداگانه پاک کنید.

همه‌ی فرمان‌ها و جست‌وجوها فقط در گفت‌وگوی خصوصی با ربات کار می‌کنند و در گروه پاسخ داده نمی‌شود. در حالت `private` فقط مدیر و شناسه‌های مجاز می‌توانند جست‌وجو کنند. در حالت `public` هر کاربر می‌تواند در چت خصوصی خودش جست‌وجو کند، اما آپلود فایل همچنان فقط برای مدیران و کاربران ثبت‌شده است. عمومی‌کردن یعنی هر کاربر تلگرام می‌تواند داده‌های واردشده را جست‌وجو کند.

متن‌های کنسول و لاگ سرور انگلیسی‌اند؛ متن‌هایی که در گفت‌وگوی ربات به کاربر نشان داده می‌شوند فارسی باقی می‌مانند.

نام‌های نمایشی هدر سراسری‌اند: برای نمونه، `/header_set NATIONAL_CODE = کد ملی` نام `NATIONAL_CODE` را در پیام نتیجه و فایل TXT برای تمام CSVهای قبلی و بعدی به «کد ملی» تغییر می‌دهد، حتی اگر آن ستون برای جست‌وجو انتخاب نشده باشد. این فقط نام نمایشی است؛ داده‌ی CSV و ستون‌های قابل جست‌وجو تغییر نمی‌کنند. هدرهای تکراری با نام اصلی یکسان همگی همان نام نمایشی را می‌گیرند. با `/header_remove NATIONAL_CODE` نام اصلی برمی‌گردد.

> دیتابیس‌های نسخه ۲ و ۳ به‌صورت خودکار به schema جدید ارتقا می‌یابند؛ فایل‌های CSV و داده‌های جست‌وجوی موجود حذف نمی‌شوند.

## تقسیم فایل CSV بزرگ

اسکریپت `split_csv_for_bot.py` فایل بزرگ را بدون شکستن رکوردهای CSV به قطعه‌های کوچک‌تر تقسیم می‌کند. این اسکریپت از RAM محدودی استفاده می‌کند و متن‌های چندخطی داخل فیلدهای quoted را نیز درست مدیریت می‌کند.

### فایل دارای header

```bash
cd /telegram_csv_search
mkdir -p data/parts
./venv/bin/python split_csv_for_bot.py \
  data/bank.csv \
  data/parts \
  --max-mb 19.0 \
  --has-header
```

خروجی:

```text
bank_part_001.csv
bank_part_002.csv
bank_part_003.csv
```

با گزینه `--has-header`، header در ابتدای تمام قطعه‌ها تکرار می‌شود.

اگر فایل از سقف ارسال تکی Telegram بزرگ‌تر است، آن را به قطعه‌های کوچک‌تر تقسیم کنید. برای ارسال با حساب Premium، سقف امن نمونه‌ی ۳۸۰۰ مگابایت است:

```bash
./venv/bin/python split_csv_for_bot.py \
  data/bank.csv \
  data/parts \
  --max-mb 3800 \
  --has-header
```

قطعه‌ها را یکی‌یکی به ربات بفرستید؛ هر قطعه جداگانه در صف ورود اطلاعات قرار می‌گیرد.

### فایل بدون header

```bash
./venv/bin/python split_csv_for_bot.py \
  data/bank.csv \
  data/parts \
  --max-mb 19.0
```

### تغییر prefix خروجی

```bash
./venv/bin/python split_csv_for_bot.py \
  data/bank.csv \
  data/parts \
  --max-mb 19.0 \
  --has-header \
  --prefix customer_data
```

برای محدودیت Telegram، مقدار `19.0` مگابایت انتخاب امنی است. قطعه‌ها را یکی‌یکی برای ربات ارسال کنید.

اگر یک رکورد به‌تنهایی از اندازه قطعه بزرگ‌تر باشد، ابزار خطا می‌دهد؛ زیرا رکورد CSV نباید نصف شود.

## رفتار header و ستون‌ها

وقتی `CSV_HAS_HEADER=true` باشد، ردیف اول هر فایل به‌عنوان header خوانده می‌شود و همان header در نتایج استفاده می‌شود.

مثال:

```csv
national_id,fullname,mobile,address
123,حسین,09120000000,تهران
```

ربات این فیلدها را همان‌طور نمایش می‌دهد:

```text
national_id: 123
fullname: حسین
mobile: 09120000000
address: تهران
```

اگر فایل دیگری چنین ساختاری داشته باشد:

```csv
id,name,email
456,ثمین,samin@example.com
```

فقط همان ستون‌های موجود نمایش داده می‌شوند. برای این رکورد چیزی به نام `address` ساخته نمی‌شود.

برای فایل‌های بدون header:

```env
CSV_HAS_HEADER=false
CSV_COLUMN_NAMES=column_1,column_2,name,birth_date,phone
```

در این حالت نام ستون‌ها از روی جایگاه آن‌ها تعیین می‌شود.

## import فایل‌های جدید

پس از قرار دادن CSV جدید در پوشه `data`:

```bash
sudo -u csvsearch /opt/telegram_csv_search/venv/bin/python \
  /opt/telegram_csv_search/import_csv.py
```

در محیط container:

```bash
./venv/bin/python import_csv.py
```

برای پردازش دوباره همه فایل‌ها:

```bash
./venv/bin/python import_csv.py --force
```

برای ساخت مجدد indexها:

```bash
./venv/bin/python import_csv.py --rebuild-indexes
```

برای توقف در اولین خطا:

```bash
./venv/bin/python import_csv.py --stop-on-error
```

## خطاهای متداول

### خطای نبودن توکن

```text
Configuration error: TELEGRAM_BOT_TOKEN is required
```

در Railway متغیر زیر را اضافه کنید:

```env
TELEGRAM_BOT_TOKEN=توکن_واقعی_ربات
```

### خطای دسترسی کاربر

```text
Access denied.
```

بررسی کنید آیدی عددی شما در این متغیر باشد:

```env
ALLOWED_USER_IDS=149772217
```

### خطای نبودن دیتابیس

در نسخه جدید، `bot.py` باید دیتابیس خالی را خودکار بسازد. اگر نسخه قدیمی دارید، از نسخه جدید استفاده کنید یا این دستور را اجرا کنید:

```bash
./venv/bin/python -c "from config import load_settings; from database import connect, initialize_database; s=load_settings(); c=connect(s.database_path); initialize_database(c); c.close()"
```

### خطای `ModuleNotFoundError: dotenv`

یعنی Python اشتباه اجرا شده است. از Python virtualenv استفاده کنید:

```bash
./venv/bin/python bot.py
```

یا:

```bash
./venv/bin/python -m pip install -r requirements.txt
```

### خطای systemd در Railway

```text
System has not been booted with systemd as init system
```

در Railway نباید `systemctl` اجرا شود. Start Command را روی این مقدار بگذارید:

```bash
./railway_start.sh
```
